# Dependencies

How PEZ$ stays independent of GitHub/registry availability and how to check for
new versions of the packages that matter.

## Posture

- **Go deps are vendored.** `vendor/` is committed; `go build`/`go test` use it
  automatically (`-mod=vendor`), so builds never fetch from
  GitHub. `go mod verify` checks the downloaded module cache; it does not prove
  the contents of `vendor/`. `make deps-verify` additionally regenerates the
  vendor tree from a clean staged source copy and requires an exact diff match.
- **npm resolution is pinned to the official registry.** `web/.npmrc` selects
  `https://registry.npmjs.org/`, rewrites stale registry hosts, and saves exact
  versions. The lockfile contains no mirror URLs, and both `npm audit` and
  `npm audit --omit=dev` report zero vulnerabilities at the September 11 baseline.
- **Zero-CDN font sovereignty (offline self-hosted).** Google Fonts
  (`fonts.googleapis.com` / `fonts.gstatic.com`) has been completely removed.
  IBM Plex Sans and IBM Plex Mono WOFF2 font files are self-hosted in
  `web/assets/fonts/` and served directly by the Go backend with immutable cache
  headers (`Cache-Control: public, max-age=31536000, immutable`) and registered
  MIME types (`font/woff2`, `font/woff`, `font/ttf`). No external requests are
  made for typography.
- **The Hyperliquid wire layer is first-party.** The `go-hyperliquid` SDK was
  removed (June 2026); its signing core and wire-action types were forked
  in-tree (MIT): `internal/infrastructure/signing/l1action.go` (msgpack action
  hash + EIP-712 phantom-agent signing) and
  `internal/infrastructure/exchange/hlwire.go` (action structs + float wire
  formatting). Byte-level behavior is pinned by recorded goldens in
  `hlwire_golden_test.go` — recorded against SDK v0.36.0 outputs at fork time.
  Do not change wire structs, tags, or field order without re-validating real
  orders against the exchange. Everything still flows through the `Exchange`
  port in `internal/ports/exchange/exchange.go`.
- **Updates are deliberate, not automatic.** Run `make deps-check` on a cadence,
  review, then bump explicitly (procedure below).

## Core packages to watch closely

| Package | Why it matters |
|---------|----------------|
| `github.com/ethereum/go-ethereum` | ECDSA + EIP-712 signing primitives under the forked signing core. **Primary.** |
| `github.com/vmihailenco/msgpack/v5` | L1 action hashing — encoding details are part of the signature. |
| `lightweight-charts` (npm) | Chart runtime (pinned v5.2.1, bundled into `web/dist`). Compiled with build-time null safety for `barStyleFnMap` in `web/build.mjs`. |
| `esbuild` (npm) | Declared production bundle compiler (v0.28.2) used directly by `web/build.mjs`. |
| `vitest`, `jsdom` (npm) | Dev-only test runner (v4.1.11) and DOM runtime (v30.0.1); pinned exact versions with zero audit vulnerabilities. |

`lightweight-charts` is pinned exactly (no semver range) and statically
imported by `web/src/chart/lightweight-chart-core.js`, so the browser runtime
and lockfile cannot drift independently. `web/build.mjs` incorporates a
dedicated `lightweightChartsNullSafetyPlugin` that guards internal
`barStyleFnMap` calls against null bar references during rapid zoom/pan churn
and conflation recalculation, neutralizing upstream `Value is null` exceptions.
Production indicator implementations live in `web/src/chart/`; CVD parity with
the former reference package is pinned by golden values in
`web/src/chart/__tests__/cvd.test.js`.

CCXT is intentionally not a dependency. PEZ needs Hyperliquid-specific candle
subscriptions, `candleSnapshot` caching/repair, HIP-3 dex routing, account-mode
reconciliation, and byte-stable signing. CCXT's normalized multi-exchange
surface would sit above or beside those first-party paths rather than replace
them, while adding a second symbol/timeframe/error model and—in this Go
backend—a separate JavaScript/Python runtime boundary. Reconsider CCXT only if
the product adds a genuine multi-exchange read-only adapter; keep execution and
the canonical Hyperliquid candle path first-party.

The real-browser release smoke has no npm browser-driver dependency.
`scripts/chart_live_smoke.mjs` drives Opera/Chromium through its built-in Chrome
DevTools Protocol endpoint, using Node's native WebSocket client. Opera/Chromium
CDP on `127.0.0.1:9222` is the default; if that port is down the harness launches
Opera (then Chrome/Chromium) with an isolated profile and stops it on exit.
Safari WebDriver remains an explicit fallback when `PEZ_CDP_URL` is set to an
empty string. Set `PEZ_CDP_NO_LAUNCH=1` to require an already-running debugger,
and `PEZ_BROWSER` to override the binary. Production bundles and the server do
not import any smoke-only code.

```sh
node scripts/chart_live_smoke.mjs
```

Use `PEZ_URL=http://127.0.0.1:<port>` to target a non-default application
listener. `PEZ_CDP_URL` overrides the browser endpoint.

No dependency install, lockfile mutation, or browser download is required.

Lower-risk infra (`gin`, `gorilla/websocket`, `prometheus/client_golang`) is
tracked by `make deps-check` but rarely urgent.

## Checking for new versions

```sh
make deps-check
```

Runs `go list -mod=readonly -m -u all` (preventing silent failures in vendored
trees) and `npm outdated`, surfacing the core packages first.
A `[vX.Y.Z]` annotation means a newer version exists.

With the wire layer first-party, exchange-side changes (new actions, schema
changes) must be tracked directly from the sources below.

## Update procedure

```sh
# Go: bump one module, re-tidy, re-vendor, test.
go get github.com/ethereum/go-ethereum@vX.Y.Z
make tidy        # runs `go mod tidy` + `go mod vendor`
make deps-verify # verifies module cache, regenerates vendor, requires exact match
make test

# npm (web/): bump, then re-test.
cd web && npm install --save-exact lightweight-charts@X.Y.Z
npm audit --omit=dev && npm audit && npm run test:run
```

For a `lightweight-charts` bump, also run the checklist in
[CHART.md](CHART.md) (zOrder shape, `positionsLine`, conflation historical
`update`, autoSize resize, overlay `Value is null`) and isolated
`scripts/chart_live_smoke.mjs` on `:5002`.

For any **trading/execution-affecting** bump (`go-ethereum`, `msgpack` — both
feed the signing path; the golden tests in
`internal/infrastructure/exchange/hlwire_golden_test.go` must stay green
unchanged), run [LIVE_VALIDATION_RUNBOOK.md](LIVE_VALIDATION_RUNBOOK.md)
before treating it as release-ready.
